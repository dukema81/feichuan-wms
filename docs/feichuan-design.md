# 飞传WMS系统建设方案

> 版本｜V1.0　编制｜飞传供应链科技（苏州）有限公司 · 仓储信息化项目组　分类｜企业管理系统

## 1. 项目概述

### 1.1 建设背景

飞传供应链科技为华东区域电商与制造客户提供第三方仓储托管服务，当前仓库作业仍依赖纸质单据与
Excel 台账，存在四类突出问题：

- **账实不同步**：收货、上架、拣货各环节手工登记，库存账面与货位实物经常出现 1~3 天的时间差，
  盘点差异无法追溯到人、到批次；
- **批次与效期失控**：食品与冷链物料对先进先出（FEFO）要求严格，纸质拣货单无法引导批次，
  临期库存靠人工翻查，过期出库风险高；
- **上下游脱节**：客户 ERP 的采购单、销售单通过邮件传递，仓库无法实时回传收发货状态，
  对账靠月底集中核对；
- **管理无数据**：库容利用率、库存周转、人员人效、承运商时效等关键指标缺乏系统口径，
  管理决策靠经验。

本项目立项建设「飞传 WMS 系统」，以零依赖、单机可跑、开放集成为原则，覆盖收货 → 上架 → 分配 →
拣货 → 复核 → 发运 → 盘点 → 追溯的仓储执行全链路，并预留与 ERP、MES、TMS 系统对接的完整
API 契约。

### 1.2 建设目标

| 目标 | 度量口径 | 达成标准 |
| --- | --- | --- |
| 库存实时准确 | 账实一致率 | 盘点行准确率 ≥ 96%（演示数据 96.5%） |
| 批次效期受控 | 临期批次识别 | 效期三级预警（关注/临期/过期），FEFO 分配默认开启 |
| 作业全程留痕 | 批次追溯 | 任一批次可正反向追溯到供应商 / 客户 / 运单 |
| 开放集成 | 接口契约 | 96 条 REST 路由 + OpenAPI 3.0 规范文档 + Webhook 25 类事件 |
| 低门槛交付 | 部署依赖 | 零第三方依赖，Python 标准库单进程可跑，双击 DEMO 即可演示 |

### 1.3 建设范围

- **入库作业**：到货预约（ASN）→ 到货登记 → 收货登记（超收容差拦截）→ 来料质检 →
  货位推荐上架 → 入库关闭，七态状态机 + 五道闸口；
- **出库作业**：销售/领料出库单（SO）→ 库存分配（FEFO/FIFO/LIFO）→ 波次组单 → 蛇形拣货 →
  复核打包 → 承运商发运 → 签收，八态状态机 + 闸口校验；
- **库存管理**：库存台账（批次 × 货位双维）、库存汇总、批次台账、库存流水、效期预警、ABC 分类；
- **库内作业**：循环盘点（明盘/盲盘、差异调整）、拣货面补货、库内移库、异常登记与处置；
- **主数据**：仓库 / 库区 / 货位（100 个演示货位）、物料（30 个 SKU）、供应商、客户、承运商；
- **看板报表**：仓储驾驶舱、出入库趋势、承运商绩效、客户金额 TOP、物料消耗 TOP、人员绩效、
  库区负荷、CSV 导出；
- **系统集成**：API Key（fck_ 前缀）、Webhook（HMAC-SHA256 签名）、增量同步（游标拉取）、
  外部单号映射、OpenAPI 3.0 规范。

## 2. 现场与业务蓝图

### 2.1 仓库布局

演示数据以苏州中心仓（WH-SZ01）为主仓、上海前置仓（WH-SH02）为辅仓，主仓设八个库区：

| 库区 | 类型 | 货位规模 | 用途 |
| --- | --- | --- | --- |
| A 区 | 存储区 · 整箱存储 | 4 排 × 4 列 × 3 层 = 48 位 | 整箱存储，容量 1.0 m³/位 |
| B 区 | 拣货区 · 拆零拣货 | 2 排 × 6 列 × 2 层 = 24 位 | 拆零拣货面，容量 0.45 m³/位 |
| C 区 | 冷链存储 | 2 排 × 2 列 × 2 层 = 8 位 | 冷藏/冷冻物料，效期重点管控 |
| D 区 | 越库中转 | 4 位 | 越库（Cross-docking）暂存 |
| E 区 | 不良品隔离 | 4 位 | 不合格品 / 待处置品隔离 |
| F 区 | 收货暂存 | 3 位 | 月台收货缓冲 |
| G 区 | 发货暂存 | 3 位 | 打包完成后待发运 |
| H 区 | 前置仓缓存 | 6 位 | 前置补货缓存 |

货位编码规则：`区-排-列-层`（如 `A-01-02-3`），与排/列/层的数字坐标一一对应，可直接参与
拣货路径计算。

### 2.2 核心业务主线

- **入库主线**：ERP 采购单 → ASN 预约（供应商/预约日期/月台）→ 到货登记 → 逐行收货
  （批次 + 效期）→ 抽检质检（抽检率 10%）→ 系统推荐货位上架 → 库存入账 → ASN 关闭；
- **出库主线**：ERP 销售单 → SO 创建 → 提交 → FEFO 分配（批次锁定）→ 波次组单（按承运商/
  截单时段/客户/库区）→ 下发拣货（蛇形路径 + 距离/工时估算）→ 复核打包（体积重计费）→
  发运（运单号 + 成本估算）→ TMS 签收回传；
- **库内主线**：循环盘点（盲盘/明盘）→ 差异审核 → 库存调整（盘盈/盘亏流水）→ 拣货面水位监控
  → 补货任务 → 库内移库。

## 3. 总体架构

### 3.1 技术选型原则

**零第三方依赖**。后端仅使用 Python 标准库（http.server + sqlite3 + json + re + hmac），
前端为原生 HTML/CSS/JS（hash 路由、无构建步骤）。该选型带来三个直接收益：

1. 交付物即源码，任何装有 Python 3.8+ 的机器（含 Windows 服务器、工控机）解压即可运行；
2. 无 node_modules、无数据库安装，离线环境（仓库内网）也能完整部署；
3. 代码即文档，二次开发门槛低。

### 3.2 分层架构

```
┌────────────────────────────────────────────────────┐
│ 前端  原生 HTML/CSS/JS · hash 路由 · 15 个页面        │
│       app.js(骨架/驾驶舱/设置) + 6 个业务 JS           │
├────────────────────────────────────────────────────┤
│ 接口层  96 条 REST 路由 · 统一响应包 · 多通道鉴权       │
│       限流 240/min · Idempotency-Key 幂等            │
├────────────────────────────────────────────────────┤
│ 业务内核  wms.py 纯函数（无 IO/SQL，可单测）            │
│       状态机 · 闸口 · 分配 · 路径 · 打分 · 波次 · 口径   │
├────────────────────────────────────────────────────┤
│ 数据层  SQLite（WAL 模式）· 26 表 + 索引 · 全局写锁     │
└────────────────────────────────────────────────────┘
```

### 3.3 业务内核（wms.py）

业务内核约 750 行纯函数，无 IO、无 SQL，全部可用单元测试覆盖：

| 模块 | 关键函数 | 说明 |

| 状态机 | `ASN_FLOW` / `SO_FLOW` / `ST_FLOW`、`can_move` / `next_stage` | 三套单据状态机 |
| 闸口 | `asn_gate` / `so_gate` / `st_gate` / `count_diff` | 状态推进前置条件校验 |
| 库存分配 | `alloc_lots` / `multi_alloc` / `avail_qty` | FEFO/FIFO/LIFO，部分满足与缺量 |
| 货位 | `loc_score` / `recommend_location` / `pick_seq` / `pick_path` / `path_distance` / `pick_minutes` | 容量/集中度/ABC/低层打分，蛇形路径 |
| 健康度 | `expiry_level` / `turnover` / `days_on_hand` / `dead_stock` / `abc_classify` / `inv_level` | 效期/周转/呆滞/ABC/水位 |
| 波次 | `wave_key` / `wave_group` / `sort_orders` / `priority_score` / `wave_balance` | 四种组波规则与拆分 |

### 3.4 数据模型（26 表）

- **组织与安全**：`users`（8 账号）、`sessions`（会话令牌）、`rules`（12 条业务规则）、
  `op_logs`（操作日志）；
- **仓库主数据**：`warehouses` / `zones` / `locations`（含 capacity/used_cube 体积占用）；
- **往来与物料**：`items` / `suppliers` / `customers` / `carriers`；
- **入库**：`asns` / `asn_items`（批次、效期、质检状态）/ `putaway_tasks`（推荐货位）；
- **出库**：`orders` / `order_items` / `allocations`（批次锁定）/ `waves` / `pick_tasks`
  （拣货顺序）/ `packages` / `shipments`；
- **库存**：`lots`（批次账 qty_in/qty_out）/ `stocks`（批次 × 货位，qty/allocated/frozen）/
  `moves`（11 类库存流水）；
- **库内**：`stocktakes` / `stocktake_items` / `replenish_tasks` / `transfers` / `exceptions`；
- **集成**：`change_log`（增量游标）/ `api_keys` / `webhooks` / `webhook_deliveries` /
  `idem_keys`（幂等缓存）/ `ext_mappings`（外部单号映射）。

库存入账保持四处同步：`stocks` 行、`lots.qty_in`、`locations.used_cube`、`moves` 流水，
任何调整（上架/拣货/移库/补货/盘盈亏）都走同一入口，保证账、批、位、流四方一致。

## 4. 核心业务规则与口径

### 4.1 三套状态机与闸口

**ASN 入库状态机**（7 态 + 取消）：
草稿 → 已预约 → 已到货 → 收货中 → 已收货 → 已上架 → 已关闭。

| 目标状态 | 闸口条件 |
| --- | --- |
| 已预约 | 供应商启用、有明细行、已填预约日期 |
| 已到货 | 已登记实际到货时间，且当前处于已预约 |
| 已收货 | 收货完成度 100%，无未处置收货差异 |
| 已上架 | 质检全部判定且合格（可让步接收），上架任务全部完成 |
| 已关闭 | 库存已正式入账（存在上架流水） |

**SO 出库状态机**（8 态 + 取消）：
草稿 → 已提交 → 已分配 → 拣货中 → 已拣货 → 已复核 → 已发运 → 已签收。
关键闸口：已分配要求满足率 100% 并生成分配明细；已复核要求有包裹；已发运要求承运商启用且
运单号已生成；已签收要求登记签收时间。

**ST 盘点状态机**（5 态）：草稿 → 盘点中 → 待审核 → 已调整 → 已关闭。
待审核要求全部货位已录实盘；已调整仅限仓储经理/盘点审核/管理员放行，放行即按差异生成
盘盈/盘亏流水并修正库存与货位体积。

### 4.2 库存分配口径

- 可用量 = 账面 − 已锁分配 − 冻结（`avail = qty - allocated - frozen`）；
- **FEFO**（默认）：按批次有效期升序分配，先到期先出；
- **FIFO**：按入库时间升序；**LIFO**：反向；
- 允许部分满足：单行缺量时订单保持「已提交」并自动生成「库存不足」异常单，
  满足率低于 100% 时闸口拦截后续推进。

### 4.3 货位推荐与拣货路径

- 货位打分（`loc_score`）：容量不足直接出局（-1）；先填满优先 +30；同 SKU 集中 +25；
  A 类物料进拣货位 +20；低层优先（人工搬运）；搬运距离越近越高；
- 候选库区链：冷链 C→A，A 类新品 B→A，其余 A→B，跨区兜底保证有位可放；
- 蛇形拣货：奇数排正向走列、偶数排反向走列，路径距离按排间距 8 m、列间距 1.2 m 估算，
  拣货工时 = 每行 0.35 分钟 + 步行距离 ÷ 1.1 m/s。

### 4.4 效期与库存健康

- 效期四档：已过期 / 临期（≤30 天）/ 关注（≤90 天）/ 正常，阈值由规则 `expiry_warn_days` 控制；
- 周转次数 = 期间出库成本 ÷ 平均库存；可售天数 = 平均库存 ÷ 日均出库成本；
- 呆滞判定：超过 90 天（`dead_stock_days`）无出库流水；
- ABC 分类：按货值金额降序，用「加入本行之前」的累计占比判定（A ≤ 70%、B ≤ 90%），
  保证最大项必为 A 类。

### 4.5 波次组单

四种规则：按承运商（默认）、按截单时段、按客户、按库区。单波上限 12 单（`wave_max_orders`），
超限自动拆分；组波前按「优先级 + 截单时间 + 客户等级」排序（特急 < 加急 < 普通）；
波次均衡度用各组行数的变异系数量化，越低越均衡。

## 7. 集成设计（预留对接）

三通道集成 + 一套映射，全部接口契约见《飞传WMS系统 REST 接口契约》：

- **API Key**：`fck_` 前缀，服务端仅存 SHA-256 摘要；read / write 两级 scope，
  头 `X-Fc-Key` 携带，只读 Key 调写接口返回 403；
- **Webhook**：订阅 25 类业务事件（asn.created / asn.received / asn.qc / asn.stage /
  asn.cancelled / putaway.done / order.created / order.allocated / order.picked /
  order.packed / order.shipped / order.stage / order.cancelled / wave.created /
  wave.picked / stocktake.created / stocktake.adjusted / stock.moved / stock.transferred /
  item.created / item.updated / rule.updated / exception.created / exception.closed 等）；
  投递签名 `HMAC-SHA256(secret, timestamp + "." + body)`，头 `X-Fc-Event / X-Fc-Timestamp /
  X-Fc-Signature / X-Fc-Delivery`；失败按 30/60/120 秒退避重试，最多 3 次；
- **增量同步**：`GET /api/sync/changes?since=<游标>&limit=`，游标为 `change_log.id`，
  单页上限 500，适合 ERP/TMS 定时对账；
- **外部映射**：`ext_mappings` 保存 ERP 单号 ⇄ WMS 单号映射，支持正反查。

令牌多通道携带（应对反向代理改写头）：`Authorization: Bearer` → `X-Fc-Token` →
`X-Auth-Token` → Cookie（wms_token）→ 查询串 `?token=` → 请求体 token 字段。
POST 支持 `Idempotency-Key` 头实现幂等重放；全局限流 240 次/分钟。

- **并发**：SQLite WAL 模式 + `busy_timeout=20s`，应用层全局写锁串行化 `/api/` 请求，
  演示规模（百级货位、万级流水）下响应 < 50 ms；
- **可观测**：`/api/health` 健康检查（进程/库态/单量），`op_logs` 全量审计操作人/动作/单号；
- **数据安全**：单文件库便于备份（拷贝即走），WAL 支持断电恢复；
- **演示友好**：种子数据确定性生成（固定随机种子），每次重建库数据完全一致，便于培训与验收。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 仓库断网 | 单机部署 + 本地 SQLite，断网不影响仓库内作业 |
